BrickLabo by SDU7 — Aide v0.1.39

English

Guide des boutons, menus clic droit, réglages et raccourcis. Certaines actions apparaissent uniquement dans la rubrique concernée ou lorsqu’une référence est sélectionnée. Un bouton grisé signifie que ses données ou conditions manquent.

Aperçus des sets et recherche globale — v0.1.38

Dans Sets réalisables avec Mon stock, le tableau du haut affiche la photo de chaque set. Faire glisser le bord d’un en-tête pour redimensionner une colonne, y compris Set. Cliquer sur un en-tête pour trier : la photo reste liée au bon set. Les miniatures utilisent le cache partagé et ses limites habituelles.

Dans les catalogues de sets Rebrickable, BrickLink et Alternatifs, le bouton MOC par mot clé / créateur ouvre une recherche globale. Saisir falcon dans le catalogue puis ouvrir ce bouton : le mot clé est repris. Cliquer sur Rechercher pour consulter les MOC et alternatives publiés sur Rebrickable, même si aucun set n’est possédé. La source et les filtres du catalogue ne limitent pas cette recherche en ligne.

Stock, imports et annulation — v0.1.37

Mon stock contient les pièces en vrac ; Mon stock set contient les sets et leurs composants enregistrés. Le tableau inférieur affiche les quantités totales possédées, les aperçus, le tri par en-tête et le double-clic d’une pièce. Retirer un set supprime ses composants ou les déplace vers le vrac.

Importer une collection accepte Rebrickable CSV et BrickLink CSV / TXT tabulé / XML. Choisir la source et la destination : un set vers le vrac est décomposé ; des pièces vers les sets s’attachent à un set existant ou à un inventaire personnel nommé. Les références et inventaires doivent être présents localement ; un inventaire incomplet bloque le lot. Annuler la dernière action / Ctrl+Z annule le dernier lot du stock ou de la file d’étiquettes. Une modification ultérieure incompatible bloque l’annulation. Le bouton Rapport de migration du stock indique les anciens inventaires incomplets.

Les exports Rebrickable séparent les sets du vrac sans compter deux fois leurs composants. Les recherches de sets combinent le vrac et les sets autorisés. Réserver sets ou pièces avec le filtre de stock ne supprime aucune donnée ; chaque proposition est évaluée séparément.

Recherche de MOC et alternatives

Depuis les catalogues de sets, les rubriques de stock ou les fenêtres de recherche, saisir falcon, le nom exact du profil d’un créateur, ou les deux. La recherche ne filtre pas les résultats selon les sets possédés. Le mode public en ligne charge une page à la fois ; Charger la suite continue. Les MOC originaux et les alternatives sont inclus par défaut ; les filtres Constructions alternatives uniquement et Notices gratuites uniquement sont facultatifs. Sélectionner un résultat recherche sa photo et les sets de départ indiqués par Rebrickable. Leurs liens permettent de consulter les sets pour préparer un achat ; un MOC original peut ne pas avoir de set de départ. Les résultats déjà consultés sont un cache local non exhaustif. Le bouton Rebrickable ouvre la même recherche dans le navigateur.

L’API v3 ne propose pas de recherche globale ni les inventaires complets des MOC. Les pages publiques peuvent changer ou refuser l’accès. Les suggestions depuis le stock passent par les sets reconstituables ; vérifier pièces et notices sur le site.

Plusieurs modèles par étiquette

Éditeur d’étiquettes → Ajouter une pièce ouvre le catalogue. Choisir une référence, sa couleur et 3D / photo. Le visuel et la référence ont leurs propres calques. Déplacer, redimensionner, dupliquer, masquer ou supprimer chacun, puis Appliquer pour conserver la composition à la réimpression.

Sauvegardes séparées

Dans Sauvegardes, choisir les familles puis Exporter les familles choisies. Chaque famille reçoit son propre JSON : étiquettes, couleurs de catégorie, vues / rendus 3D, vrac, sets / composants, file d’étiquettes, préférences. Les clés API sont facultatives et décochées par défaut. Restaurer plusieurs JSON remplace uniquement ces familles après validation. Ces fichiers ne contiennent pas les photos locales, LDraw ou les inventaires complets des catalogues ; la sauvegarde ZIP complète reste disponible.

Temporaires, caches et dossiers

Espace disque règle les budgets des miniatures : 32 Mio RAM / 256 Mio disque par défaut ; disque à 0 = RAM uniquement. Les rendus identiques partagent un cache RAM borné et les demandes simultanées sont regroupées. Purger les miniatures ou temporaires protège les sessions actives et fichiers de données référencés. Python / Qt utilisent une session de Donnees/temp, configurée avant Qt ; les sessions abandonnées sont nettoyées.

À la racine : BrickLabo.exe, LISEZ-MOI.txt, PROJET_GITHUB.url ; dossiers app, ressources, documentation, licences, puis Donnees au lancement. Bibliothèques dans app/lib, aucun BAT nécessaire. Les bases SQLite utilisent win32-longpath sous Windows, avec les verrouillages habituels. Les chemins sont calculés depuis le dossier du logiciel ; les noms courts augmentent la marge sans supprimer les limites Windows / bibliothèques. Lire l’unique NOUVEAUTES.txt.

Inventaires TXT des sets BrickLink

Sélectionnez un set BrickLink puis cliquez sur « Ajouter l’inventaire depuis un fichier TXT » dans le volet droit ou dans sa fenêtre de composition. Choisissez le TXT téléchargé sur BrickLink. Le nom S-75192-1.txt est vérifié contre le set sélectionné ; un nom générique set.txt est aussi accepté par ce bouton. Le fichier S-référence.txt peut également être importé depuis Mise à jour des données si le catalogue Sets est déjà importé.

Références, noms, couleurs BrickLink, quantités et indicateurs Extra, Alternate, Counterpart et Match ID sont conservés dans SQLite. Le TXT peut être supprimé après confirmation de l’import. Le nouvel inventaire remplace le précédent de ce set et a priorité sur le cache API et le rapprochement Rebrickable. Les variantes et équivalents sont conservés mais exclus des ajouts automatiques pour éviter les doubles comptes ; les pièces supplémentaires sont incluses. Les quantités déjà présentes dans Mon stock ne changent pas lors d’un réimport. Double-cliquez sur le set pour consulter les pièces ; les fonctions stock et étiquettes utilisent l’inventaire enregistré. Les pièces et mini-figures peuvent retrouver les sets importés qui les contiennent.

Sauvegardes et restauration

Le bouton Sauvegardes permet de créer un ZIP privé et vérifié de Donnees avec une copie cohérente de SQLite. Stock, inventaires, réglages, clés API, images et notices sont inclus ; caches, logs, téléchargements et temporaires sont exclus. Les fichiers situés hors de Donnees ne sont pas copiés. Gardez les sauvegardes privées car elles contiennent les clés API. Placez-les dans un dossier extérieur à Donnees.

Restaurer prépare les fichiers et vérifie leur intégrité sans modifier les données en cours. Fermez puis relancez BrickLabo pour appliquer la restauration. Avant le remplacement, l’état précédent est conservé dans Donnees_avant_restauration_… à côté du logiciel. Annuler la restauration prévue permet de garder les données actuelles. Les anciennes copies et sauvegardes ne sont pas supprimées automatiquement ; vous pouvez les archiver ou les supprimer après vérification.

Langue du logiciel

Cliquer sur Langue, choisir Français ou English et enregistrer. Fermer puis relancer BrickLabo pour appliquer la langue à toutes les fenêtres. Les noms, catégories et références des bases restent inchangés. Les fenêtres natives Windows de fichiers et d’imprimante suivent la langue d’affichage de Windows. Les fichiers AIDE.en.html, README.en.md, SOURCES_ET_LICENCES.en.html et NOUVEAUTES.txt sont disponibles en anglais.

v0.1.30 — Constructions alternatives et noms courts

Catalogue de sets : clic droit sur un set, puis « Voir les constructions alternatives ». Renseigner la clé Rebrickable dans API Keys. La fenêtre affiche les constructions du set choisi, leurs créateurs, pièces et photos. « Charger la suite » affiche la page suivante ; un double-clic ouvre la construction et ses notices sur Rebrickable. Certaines notices sont payantes. Le stock reste inchangé.

Les noms des nouveaux caches et temporaires sont raccourcis. Une erreur de chemin lors d’un export interrompt la génération avec un message ; les fichiers déjà terminés restent disponibles. Aucun historique de réussite n’est ajouté pour un lot interrompu. Une miniature non enregistrable reste en mémoire ; voir les logs.

Exporter le stock vers Rebrickable (v0.1.31)

Dans Mon Stock, choisir Exporter tout mon stock vers Rebrickable. Les deux onglets distinguent les pièces en vrac et les sets possédés. Convertir BrickLink (API RB) recherche les références et couleurs correspondantes. Corriger les lignes ambiguës avant export.

Importer stock_sets.csv dans My Set Lists, et stock_pieces.csv dans My Parts Lists. Les pièces attribuées aux sets ne sont pas recomptées dans le vrac. Consulter stock_rapport.txt avant import. Éviter de réimporter plusieurs fois les mêmes listes ou de compter les mêmes sets dans plusieurs listes actives. Les mini-figs sans inventaire et les références inconnues sont signalées.

Contrôle et corrections v0.1.39

Les lectures courtes de SQLite partagent une connexion en lecture seule, protégée entre les tâches. Les réimports de pièces et changements de visuel identiques évitent les mises à jour inutiles et les réécritures FTS5. Les catégories calculées des mini-figures sont conservées au réimport.

Les photos décodées utilisent un cache RAM borné de 32 Mio ; les textes LDraw un cache de 8 Mio. Les lectures répétées d'une photo ne relisent plus son registre JSON. Les aperçus rapides regroupent les demandes et terminent sur la dernière sélection. Une purge ou un changement de réglage empêche une ancienne tâche de remettre son résultat dans le cache.

Les imports d'inventaires personnels sont atomiques : une erreur annule ensemble leur création et l'ajout au stock. Les ajouts multiples constituent une seule action annulable. Les changements de couleur conservent le total et l'annulation même lorsque deux lignes fusionnent. Les mises à jour BrickArchitect restaurent l'ancien catalogue et son archive si leur publication échoue.

Les téléchargements intermédiaires BrickArchitect utilisent la session de Donnees/temp et sont supprimés en cas d'échec. Le bouton Nettoyer les temporaires de plus de 7 jours traite aussi l'ancien dossier Donnees/temporaires, affiché dans Espace disque s'il existe. Les fichiers référencés, récents et les sessions actives sont protégés. Les sauvegardes complètes excluent ces deux dossiers. La fermeture attend les tâches en cours avant de fermer les archives et nettoyer la session. Consulter les notices ne crée plus de dossiers vides.

Le lanceur est recompilé avec l'icône d'origine en sept tailles au format bitmap Windows classique. La fabrication contrôle que les images intégrées au .exe correspondent au .ico fourni et que les dépendances du paquet correspondent aux versions fixées dans app/requirements.txt. L'affichage dans l'Explorateur Windows reste à confirmer sur un PC Windows.
